Gestion de Tickets : System

Use Case - Gestionar Tickets link

Properties
Name Value
Description

describe las funcionalidades necesarias para gestionar el ciclo de vida de los tickets asociados a los activos. Incluye la creación y consulta de tickets por cualquier usuario autenticado; modificación, reasignación y cierre por responsables y gestores; y eliminación lógica sólo por roles autorizados (Administrador / Gestor de Tickets). El sistema validará permisos y estado del ticket antes de cada operación

Use Case Note
■ Workflow
    • El actor autorizado accede al módulo de Gestión de Tickets.
    • Puede realizar acciones como crear, modificar, reasignar, cerrar o eliminar un ticket.
    • El sistema valida permisos y estado antes de permitir la operación.
    • El sistema actualiza la base de datos y registra la acción en el historial.
    • El sistema envía notificaciones a los actores involucrados.
■ Business Logic
    • El sistema debe validar los permisos del usuario antes de cada acción.
    • El sistema debe registrar todas las operaciones en el log de auditoría.
    • El sistema debe garantizar trazabilidad e integridad de la información de los tickets.
■ Decisions
    • Solo Administrador y Gestor de Tickets pueden eliminar tickets.
    • Todos los usuarios autenticados pueden crear tickets.
    • Los responsables pueden actualizar el estado y agregar comentarios.
■ Follow-up
    • Definir reglas de notificación (correo, sistema interno, ambos).
    • Confirmar políticas de retención de datos de tickets históricos

Scenario
Steps
1. Gestor de Tickets
2. Administrador
3. El actor autorizado accede al sistema.
4. Ingresa al módulo de Gestión de Tickets.
5. Selecciona la acción que desea realizar (crear, modificar, reasignar, cerrar, eliminar).
6. El sistema solicita la información necesaria para ejecutar la acción.
7. El actor confirma la operación.
8. El sistema valida permisos y estado del ticket.
9. El sistema aplica la operación solicitada.
10. El sistema actualiza los registros e historial.
11. El sistema notifica a los usuarios involucrados.

Scenario2
Steps
1. Usuario sin permisos:
2. En el paso 8, si el usuario no cuenta con permisos, el sistema rechaza la operación y muestra mensaje de error.

Scenario3
Steps
1. Ticket inexistente o inválido:
2. En el paso 6, si el ticket seleccionado no existe o está cerrado, el sistema cancela la acción e informa al usuario.

Scenario4
Steps
1. Error técnico:
2. Si ocurre un error al guardar la operación (paso 9), el sistema muestra un mensaje de error y no aplica cambios.

Preconditions El usuario debe estar autenticado en el sistema de gestión de activos. El usuario debe tener permisos de gestión de tickets según su rol (Administrador, Gestor de Tickets, Responsable). Gestionar Tickets
Post-conditions Los tickets quedan actualizados según la acción realizada (crear, modificar, eliminar, reasignar, cambiar estado). El sistema mantiene trazabilidad completa de cada operación. Los actores involucrados reciben notificaciones de los cambios realizados.
Author
Assumptions Se asume que el sistema está disponible durante la operación. Se asume que existen técnicos disponibles para atender los tickets. Se asume que la gestión de tickets cumple con las políticas internas de soporte y auditoría.
