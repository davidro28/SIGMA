Description

permite reasignar un activo ya asignado a un nuevo usuario o área. El sistema valida la disponibilidad del activo, los permisos de quien realiza la acción y registra la reasignación, notificando a las partes involucradas.

Use Case Note
■ Workflow
    • El administrador selecciona un activo ya asignado, elige un nuevo usuario/área y confirma la reasignación.
■ Business Logic
    • Solo los activos disponibles y en estado activo pueden ser reasignados.
    • Se debe conservar un historial de asignaciones previas.
■ Decisions
    • Puede requerirse justificación del motivo de reasignación.
■ Follow-up
    • Notificar al usuario anterior y al nuevo asignatario.(opcional)

Scenario
Steps
1. Administrador
2. El administrador accede al sistema y selecciona la opción Reasignar Activo.
3. El sistema muestra la lista de activos asignados.
4. El administrador selecciona un activo específico.
5. El sistema valida existencia y estado del activo.
6. El sistema solicita seleccionar el nuevo usuario o área receptora.
7. El administrador selecciona al nuevo asignatario.
8. El sistema solicita confirmación de la reasignación.
9. El administrador confirma la acción.
10. El sistema actualiza la asignación del activo en la base de datos.
11. El sistema registra la acción en el módulo de auditoría.
12. El sistema notifica al usuario anterior y al nuevo asignatario(opcional)
13. El caso de uso finaliza mostrando mensaje de confirmación.

Scenario2
Steps
1. 4(a). El administrador selecciona un activo inexistente → el sistema informa que no se encontró.
2. 5(a). El activo está en estado bloqueado/mantenimiento → el sistema impide la reasignación.
3. 7(a). El nuevo asignatario no existe o no está activo → el sistema bloquea la acción.
4. 10(a). Error en la base de datos → el sistema informa error y no registra el cambio.

Preconditions El administrador debe estar autenticado en el sistema. El activo debe estar registrado y actualmente asignado. El nuevo usuario/área debe estar registrado en el sistema. Reasignar Activo
Post-conditions El activo queda reasignado al nuevo usuario/área. La acción queda registrada en el historial de auditoría. Se notifican ambas partes (usuario saliente y entrante).
Author
Assumptions Se asume que los usuarios y áreas están previamente creados y disponibles en el sistema. La reasignación es inmediata y no requiere aprobación adicional.
