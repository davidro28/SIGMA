Use Case Note
■ Workflow
    • El usuario autorizado selecciona un reporte, edita los campos necesarios y guarda los cambios.
■ Business Logic
    • El sistema debe registrar las modificaciones realizadas, incluyendo quién y cuándo las hizo.
■ Decisions
    • El sistema debe solicitar confirmación antes de guardar los cambios.
■ Follow-up
    • Notificar a los responsables sobre la modificación.

Scenario
Steps
1. Administrador
2. Tecnico de Mantenimiento
3. El actor accede al sistema y selecciona la opción Modificar Reporte.
4. El sistema muestra la lista de reportes disponibles según permisos.
5. El usuario selecciona un reporte específico.
6. El sistema valida existencia y permisos del usuario.
7. El sistema muestra los datos actuales del reporte.
8. El actor modifica los campos requeridos.
9. El sistema solicita confirmación antes de guardar.
10. El actor confirma la modificación.
11. El sistema guarda los cambios en la base de datos.
12. El caso de uso finaliza mostrando un mensaje de confirmación.

Scenario2
Steps
1. 5(a). El usuario selecciona un reporte inexistente → el sistema informa que no se encontró.
2. 6(a). El usuario no tiene permisos → el sistema rechaza la acción.
3. 9(a). El usuario intenta modificar un campo no editable → el sistema bloquea la acción.
4. 10(a). Error en la base de datos → el sistema informa error y no guarda los cambios.
