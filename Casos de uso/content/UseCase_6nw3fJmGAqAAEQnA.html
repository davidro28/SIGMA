Use Case Note
■ Workflow
    • El (Administrador, Responsable o Gestor de Tickets) accede al módulo de soporte.
    • Selecciona la opción “Crear ticket”.
    • Diligencia los campos: título, descripción del problema y categoría.
    • Confirma la creación.
    • El sistema genera un número de ticket y envía notificación al responsable.
■ Business Logic
    • El sistema debe validar que los campos obligatorios (título, descripción) estén completos.
    • Asignar automáticamente un identificador único al ticket.
    • Registrar la fecha y hora de creación.
    • Enviar una notificación al responsable asignado.
    • Cambiar el estado del ticket a “Abierto”.
■ Decisions
    • Se acordó que solo los usuarios autenticados pueden crear tickets.
    • La prioridad por defecto será “Media” si el usuario no especifica otra.
    • Se permitirá adjuntar archivos opcionalmente.
■ Follow-up
    • Revisar si se requiere un flujo de aprobación para tickets de alta prioridad.

Scenario
Steps
1. Gestor de Tickets
2. Administrador
3. Responsable
4. Actor accede al sistema de soporte y selecciona la opción “Crear Ticket”.
5. El sistema muestra el formulario de creación de ticket.
6. El actor ingresa los datos obligatorios: título, descripción, categoría y prioridad.
7. (Opcional) El actor adjunta archivos o evidencia del problema.
8. El actor confirma la creación del ticket.
9. El sistema valida la información ingresada.
10. El sistema genera un identificador único para el ticket.
11. El sistema registra la fecha y hora de creación.
12. El sistema asigna el ticket al responsable o cola correspondiente según la categoría.
13. El sistema envía una notificación al responsable asignado y al creador del ticket.
14. El sistema muestra mensaje de confirmación y el número de ticket al actor.

Scenario2
Steps
1. A1: Campos obligatorios incompletos
2. Si faltan campos obligatorios, el sistema muestra un mensaje de error.
3. El actor completa la información y vuelve a confirmar.
4. A2: Error en el envío
5. Si ocurre un fallo de comunicación, el sistema informa al actor y solicita reintentar.

Preconditions El usuario debe estar autenticado en el sistema de gestión de activos. El activo debe estar previamente registrado en la base de datos. El usuario debe tener permisos para crear tickets de soporte. Crear Ticket Soporte
Post-conditions El ticket queda registrado en el sistema con un número único de identificación. El ticket queda asignado a la cola de soporte correspondiente. El usuario recibe confirmación de la creación del ticket (notificación o correo).
Author
Assumptions Se asume que el sistema está disponible y operativo al momento de la creación del ticket. Se asume que el usuario proporciona la información mínima requerida (activo, descripción del problema, prioridad). Se asume que existen técnicos disponibles para la atención del ticket.
