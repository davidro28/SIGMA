Use Case Note
■ Workflow
    • El administrador inicia sesión en el sistema.
    • Accede al módulo de gestión de activos.
    • Localiza el activo a eliminar mediante el buscador o listado.
    • Selecciona la opción “Eliminar”.
    • Confirma la eliminación cuando el sistema solicita confirmación.
    • El sistema elimina el activo y muestra un mensaje de éxito
■ Business Logic
    • Solo los usuarios con rol de Administrador pueden ejecutar la eliminación.
    • El sistema debe verificar que el activo no tenga procesos pendientes (por ejemplo, mantenimientos o préstamos activos).
    • Se debe registrar un log con la fecha, hora y usuario que realizó la eliminación.
    • La eliminación es irreversible y debe reflejarse inmediatamente en los reportes e inventario.
■ Decisions
    • Se definió que la eliminación será lógica (marcar el activo como inactivo) en vez de física, para mantener histórico de datos.
    • El sistema mostrará un cuadro de confirmación antes de proceder.
    • En caso de eliminarse un activo con dependencias, se bloquea la acción y se informa al administrador.
■ Follow-up
    • Evaluar si debe implementarse una opción de recuperación (papelera de reciclaje) en futuras versiones.
    • Revisar políticas de retención de datos para activos eliminados.

Scenario
Steps
1. Administrador
2. El Administrador inicia sesión en el sistema de gestión de activos.
3. El Administrador navega al módulo Gestión de Activos.
4. El Administrador busca y selecciona el activo que desea eliminar.
5. El sistema muestra los detalles del activo y la opción “Eliminar”.
6. El Administrador hace clic en “Eliminar”.
7. El sistema solicita confirmación indicando que la acción es irreversible.
8. El Administrador confirma la eliminación.
9. El sistema valida que el activo no tenga procesos pendientes (por ejemplo, mantenimientos o préstamos activos).
10. Si no existen impedimentos, el sistema elimina lógicamente el activo (lo marca como inactivo o lo retira de la base de datos según la política definida).
11. El sistema registra en el historial de auditoría la fecha, hora y usuario que ejecutó la acción.
12. El sistema muestra un mensaje de confirmación de que la eliminación fue exitosa.

Scenario2
Steps
1. 8(a). Activo con procesos pendientes:
2. El sistema informa que el activo no puede ser eliminado mientras tenga procesos pendientes.
3. El Administrador puede cancelar la operación o resolver primero las dependencias.

Scenario3
Steps
1. 7(a). Cancelación del usuario:
2. Si el Administrador cancela en la ventana de confirmación, el sistema no elimina el activo y regresa a la vista de detalles.

Preconditions El administrador debe haber iniciado sesión en el sistema. Validar Usuario El activo a eliminar debe existir en el sistema. Eliminar Activo El activo no debe tener procesos pendientes (mantenimiento, préstamo u otros).
Post-conditions El activo queda marcado como eliminado (o inactivo) en la base de datos según las políticas definidas. Se registra en el historial de auditoría la acción con fecha, hora y usuario que la realizó. Los reportes e inventarios reflejan la eliminación en tiempo real.
Author
Assumptions La acción de eliminación es irreversible. La conexión a la base de datos funciona de manera estable durante la operación. El administrador conoce el impacto de la eliminación en otros módulos del sistema.
