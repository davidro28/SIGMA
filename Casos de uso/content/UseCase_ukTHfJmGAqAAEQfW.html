Description

El caso de uso "Modificar Activo" permite al Administrador actualizar la información de un activo registrado en el sistema. Esto puede incluir cambios en el nombre del activo, ubicación, estado, responsable, características técnicas, fecha de mantenimiento, entre otros.

Use Case Note
■ Workflow
    • El administrador inicia sesión en el sistema.
    • Accede al módulo de activos.
    • Busca el activo por nombre, ID o categoría.
    • Selecciona el activo deseado para editar.
    • Modifica los campos necesarios (nombre, estado, ubicación, responsable, etc.).
    • Guarda los cambios.
    • El sistema confirma la modificación y actualiza el historial de cambios.
■ Business Logic
    • El sistema debe validar que los campos obligatorios estén completos antes de guardar.
    • Si un campo contiene datos inválidos (ej. fecha incorrecta, ID duplicado), se debe mostrar un mensaje de error.
    • Cada modificación debe registrarse en un historial de auditoría con fecha, hora y usuario responsable.
    • Si el activo se encuentra asignado o en mantenimiento, solo se podrán editar ciertos campos (por ejemplo, no se puede cambiar su estado a "Disponible").
■ Decisions
    • Se acordó que solo los usuarios con rol de Administrador podrán modificar activos.
    • El sistema debe ser accesible tanto desde navegadores web como desde dispositivos móviles.
    • No se permitirá la modificación de activos marcados como "Dados de baja".
    • El historial de cambios debe ser visible desde la interfaz del activo.
■ Follow-up
    • Evaluar la posibilidad de notificar automáticamente al responsable cuando un activo sea modificado.
    • Confirmar con el área de auditoría si el log de cambios cumple con las políticas internas de trazabilidad.

Scenario
Steps
1. Administrador
2. El administrador inicia sesión en el sistema.
3. El administrador accede al módulo de "Gestión de Activos".
4. El sistema muestra la lista de activos registrados.
5. El administrador busca el activo a modificar (por ID, nombre, o categoría).
6. El sistema muestra los detalles del activo seleccionado.
7. El administrador hace clic en el botón "Modificar" o "Editar".
8. El sistema habilita los campos editables.
9. El administrador realiza los cambios necesarios (estado, ubicación, responsable, etc.).
10. El administrador guarda los cambios.
11. El sistema valida que todos los campos requeridos sean correctos y estén completos.
12. El sistema guarda los cambios en la base de datos.
13. El sistema registra la modificación en el historial de auditoría.
14. El sistema muestra un mensaje de confirmación: “Activo modificado exitosamente”.

Preconditions Modificar Activo El usuario debe haber iniciado sesión en el sistema con un rol que tenga permisos de edición de activos. El activo que se desea modificar debe existir previamente en el sistema.
Post-conditions Los cambios realizados en el activo quedan registrados en la base de datos. Se genera un historial de modificaciones para el activo. El sistema muestra confirmación de que la modificación fue exitosa.
Author
Assumptions La información ingresada por el usuario es válida y cumple con las reglas de negocio. No hay fallos de conexión a la base de datos durante el proceso de modificación. El usuario conoce los datos que necesita actualizar.
