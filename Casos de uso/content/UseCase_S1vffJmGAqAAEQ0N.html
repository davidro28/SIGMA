Use Case Note
■ Workflow
    • El administrador selecciona un reporte, confirma la eliminación y el sistema lo elimina de la base de datos.
■ Business Logic
    • Solo usuarios con rol de administrador pueden eliminar reportes.
    • La eliminación debe ser irreversible.
■ Decisions
    • El sistema debe solicitar confirmación antes de la acción.
    • Se debe registrar la eliminación.
■ Follow-up
    • Notificar a los usuarios asociados al reporte (si aplica).
    • Registrar la acción en el módulo de auditoría para trazabilidad.

Scenario
Steps
1. Tecnico de Mantenimiento
2. Administrador
3. El administrador accede al sistema y selecciona la opción Eliminar Reporte.
4. El sistema muestra la lista de reportes existentes.
5. El administrador selecciona el reporte que desea eliminar.
6. El sistema valida permisos y existencia del reporte.
7. El sistema solicita confirmación de la acción.
8. El administrador confirma la eliminación.
9. El sistema elimina el reporte de la base de datos.
10. El sistema registra la acción en el módulo de auditoría.
11. El sistema notifica a los usuarios relacionados (si aplica).
12. El caso de uso finaliza mostrando mensaje de confirmación.

Scenario2
Steps
1. 5(a). El administrador selecciona un reporte inexistente → el sistema informa que no se encuentra disponible.
2. 6(a). El usuario no tiene permisos → el sistema rechaza la acción.
3. 8(a). El administrador no confirma → el sistema cancela la operación.
4. 9(a). Error en la base de datos → el sistema informa el error y no elimina el reporte.
