Use Case Note
■ Workflow
    • El administrador accede al módulo de gestión de activos.
    • Selecciona la opción "Asignar Activo".
    • El sistema muestra la lista de activos disponibles para asignar.
    • El administrador elige un activo específico.
    • Se despliega una lista de usuarios o departamentos a los que se puede asignar el activo.
    • El administrador selecciona el destinatario de la asignación.
    • El sistema registra la asignación con fecha, usuario y activo.
    • El administrador confirma la operación.
    • El sistema actualiza el estado del activo a "Asignado".
■ Business Logic
    • El sistema debe validar que el activo esté disponible para asignar (no asignado previamente).
    • El sistema debe verificar que el usuario o departamento seleccionado esté activo y autorizado para recibir activos.
    • La asignación debe quedar registrada con datos de auditoría (fecha, usuario administrador, destinatario).
    • En caso de error o inhabilitación del activo, el sistema debe mostrar mensajes claros para el administrador.
■ Decisions
    • La asignación sólo puede ser realizada por usuarios con rol administrador.
    • Los activos que estén en mantenimiento o fuera de servicio no pueden ser asignados.
    • El sistema debe permitir reasignar activos sólo si el activo está previamente asignado y disponible para transferencia.
■ Follow-up
    • Verificar que las asignaciones se reflejen correctamente en el inventario de activos.
    • Validar auditoría de cambios para seguimiento y control.
    • Implementar alertas para activos asignados sin reporte de uso después de un período determinado.

Scenario
Steps
1. Administrador
2. El administrador inicia sesión en el sistema.
3. El administrador selecciona la opción "Asignar Activo" en el menú principal.
4. El sistema muestra la lista de activos disponibles para asignar.
5. El administrador selecciona el activo que desea asignar.
6. El sistema muestra los detalles del activo seleccionado y las opciones para asignar.
7. El administrador selecciona el usuario o departamento al que desea asignar el activo.
8. El sistema verifica la disponibilidad del activo y la validez del usuario/departamento.
9. El sistema registra la asignación, actualizando el estado del activo a "Asignado".
10. El sistema confirma que el activo fue asignado exitosamente.
11. El administrador recibe una notificación de confirmación.
12. El caso de uso finaliza con éxito.

Scenario2
Steps
1. Si en el paso 8 el activo no está disponible para asignar
2. 8(a). El sistema muestra un mensaje de error indicando que el activo no puede ser asignado.
3. 8(b). El administrador puede elegir otro activo o cancelar la operación.

Scenario3
Steps
1. Si en el paso 8 el usuario o departamento seleccionado no es válido o no está autorizado,
2. 8(a). El sistema muestra un mensaje de error indicando que la asignación no es posible.
3. 8(b). El administrador debe seleccionar un usuario/departamento válido.
