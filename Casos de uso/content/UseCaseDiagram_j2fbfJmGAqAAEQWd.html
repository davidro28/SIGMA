  Iniciar Sesion : Use Case

El usuario ingresa sus credenciales (usuario y contraseña) para acceder al sistema. El sistema valida los datos y permite o deniega el acceso.

  Asignar Rol : Use Case

El administrador, una vez autenticado en el sistema, selecciona un usuario y le asigna el rol correspondiente

  Registrar Usuario : Use Case

El administrador, tecnico, Gestor de Tickets o el responsable ingresa los datos del nuevo usuario (nombre, correo, credenciales iniciales, etc.), confirma el registro.
El sistema almacena la información, crea la cuenta y notifica la creación exitosa.

  Restablecer Contraseña : Use Case

Este caso de uso permite a los usuarios restablecer su contraseña en caso de olvido. El proceso puede ser iniciado por el propio usuario a través de la opción "¿Olvidó su contraseña?" o por el administrador desde el panel de gestión. El sistema enviará un enlace de restablecimiento al correo electrónico registrado, el cual redirigirá al usuario a una pantalla para definir una nueva contraseña segura.

  Registrar Activo : Use Case

El administrador registra un nuevo activo ingresando su nombre, número de serie (serial), y subiendo una imagen. El sistema almacena los datos y permite futuras consultas o ediciones del activo registrado.

  Solicitar Foto del Activo : Use Case

permite solicitar la carga de una fotografía del activo para complementar su registro y mejorar la identificación visual del mismo.

  Asignar Activo : Use Case

el administrador puede asignar un activo registrado a un usuario o departamento. El sistema debe permitir seleccionar el activo, elegir el destinatario y registrar la asignación con fecha y otros detalles necesarios para el control y auditoría.

  Modificar Activo : Use Case

El caso de uso "Modificar Activo" permite al Administrador actualizar la información de un activo registrado en el sistema. Esto puede incluir cambios en el nombre del activo, ubicación, estado, responsable, características técnicas, fecha de mantenimiento, entre otros.

  Eliminar Activo : Use Case

describe el proceso mediante el cual el administrador elimina un activo existente en el sistema de gestión de activos.

  Modificar Ticket : Use Case

describe el proceso mediante el cual un actor autorizado modifica un ticket previamente creado en el sistema de gestión de activos.
El actor puede actualizar campos como: descripción del problema, prioridad, estado del ticket, asignación de responsable, o adjuntar información adicional.
Una vez modificado, el sistema registra los cambios con la fecha, hora y usuario que realizó la modificación, y notifica a las partes interesadas.

  Eliminar Ticket : Use Case

describe cómo un actor autorizado elimina un ticket existente en el sistema.
El sistema valida permisos y estado del ticket antes de proceder.
Una vez eliminado, el sistema guarda un registro en el historial de auditoría y envía notificaciones a los usuarios relacionados.
La eliminación es lógica (el ticket se marca como inactivo) para preservar trazabilidad.

  Gestionar Tickets : Use Case

describe las funcionalidades necesarias para gestionar el ciclo de vida de los tickets asociados a los activos. Incluye la creación y consulta de tickets por cualquier usuario autenticado; modificación, reasignación y cierre por responsables y gestores; y eliminación lógica sólo por roles autorizados (Administrador / Gestor de Tickets). El sistema validará permisos y estado del ticket antes de cada operación

  Consultar Disponibilidad del Activo : Use Case

permite a los usuarios consultar el estado actual de un activo dentro del sistema, verificando si está disponible, en uso, en mantenimiento o reservado. El sistema validará que el usuario esté autenticado y autorizado para acceder a la información. Al realizar la consulta, se recupera el estado actualizado desde la base de datos y se muestra al usuario en una vista clara.

  Crear Solicitud de Mantenimineto : Use Case

permite que un gestor de tickets o administrador registre una solicitud de mantenimiento, ingresando la información del activo, el tipo de mantenimiento y la descripción del problema o necesidad.

  Cancelar Solicitud : Use Case

permite que un usuario autorizado cancele una solicitud previamente creada. El sistema valida que la solicitud exista y que su estado sea pendiente o en proceso, la actualiza a cancelada y registra la acción en el historial, notificando a los responsables.

  Asignar Teccnico : Use Case

permite que un administrador o gestor de tickets seleccione un técnico disponible y lo asigne a una solicitud de mantenimiento. El sistema valida la existencia del técnico, su disponibilidad y habilidades requeridas, registra la asignación y notifica tanto al técnico como al solicitante.

  Eliminar Reporte : Use Case

permite que el administrador seleccione un reporte existente y lo elimine del sistema. Antes de la eliminación, el sistema valida permisos, solicita confirmación y registra la acción en el historial.

  Modificar Reporte : Use Case

permite que un usuario autorizado edite un reporte existente. El sistema valida permisos, muestra los datos actuales, permite realizar cambios y guarda la nueva versión, manteniendo la trazabilidad de las modificaciones.

  Generar Reporte del Activo : Use Case

Este caso de uso permite que un usuario autorizado genere un reporte sobre un activo o grupo de activos. El sistema valida permisos, solicita los criterios de búsqueda, procesa la información en la base de datos y genera un reporte en el formato solicitado (PDF, Excel, etc.)..

  Reasignar Activo : Use Case

permite reasignar un activo ya asignado a un nuevo usuario o área. El sistema valida la disponibilidad del activo, los permisos de quien realiza la acción y registra la reasignación, notificando a las partes involucradas.

  Gestionar Solicitud de Mantenimiento : Use Case

permite gestionar el ciclo completo de una solicitud de mantenimiento. El sistema valida los permisos del actor, permite registrar y modificar información, asignar técnicos, cancelar solicitudes o marcarlas como resueltas.

  Modificar Solicitud : Use Case

describe la modificación de datos de una solicitud de mantenimiento previamente creada. El sistema valida permisos, estado de la solicitud y consistencia de la información antes de aplicar los cambios. Una vez modificada, se actualizan los registros en la base de datos

  Consultar Solicitud : Use Case

describe cómo los usuarios acceden y consultan el detalle de una solicitud de mantenimiento. El sistema valida permisos, recupera la información desde la base de datos y la presenta de manera clara, incluyendo datos del activo, descripción del problema, estado actual, técnico asignado y fechas relevantes.

  Validar Usuario : Use Case

se ejecuta como parte del inicio de sesión. El sistema recibe el nombre de usuario ingresado y verifica que exista en la base de datos. Si el usuario está registrado y su cuenta está activa, devuelve una respuesta positiva; si no, genera un error indicando que el usuario no existe o está inactivo.
