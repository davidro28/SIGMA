Use Case Note
■ Workflow
    • El usuario selecciona la solicitud a cancelar, confirma la acción y el sistema actualiza el estado a cancelada.
■ Business Logic
    • No se pueden cancelar solicitudes ya completadas o cerradas.
    • La cancelación requiere confirmación del usuario para evitar errores.
■ Decisions
    • Solo el solicitante o el administrador pueden cancelar solicitudes.
    • Se debe registrar la justificación de la cancelación.
■ Follow-up
    • Notificar al gestor de tickets y responsables sobre la cancelación.

Scenario
Steps
1. Gestor de Tickets
2. Administrador
3. El usuario accede al sistema y selecciona la opción Cancelar Solicitud.
4. El sistema muestra el listado de solicitudes creadas por el usuario o bajo su gestión.
5. El usuario selecciona la solicitud que desea cancelar.
6. El sistema valida que la solicitud exista y que esté en estado pendiente o en proceso.
7. El sistema solicita confirmación de cancelación.
8. El usuario confirma la acción.
9. El sistema actualiza el estado de la solicitud a cancelada.
10. El sistema registra la acción en el módulo de auditoría.
11. El sistema notifica al administrador y al gestor de tickets.
12. El caso de uso finaliza mostrando un mensaje de confirmación.

Scenario2
Steps
1. 5(a). El usuario selecciona una solicitud inexistente → el sistema muestra mensaje de error.
2. 6(a). La solicitud ya está completada o cerrada → el sistema indica que no puede cancelarse.
3. 8(a). El usuario no confirma la cancelación → el sistema mantiene la solicitud activa.
4. 9(a). Error en la base de datos → el sistema informa error y sugiere reintentar.
