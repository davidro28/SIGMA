Use Case Note
■ Workflow
    • El usuario escribe su nombre de usuario en el formulario de inicio de sesión y presiona el botón "Siguiente" o "Iniciar Sesión".
    • El sistema verifica en la base de datos si el usuario existe y si su cuenta está activa
■ Business Logic
    • Si el usuario ha fallado el inicio de sesión más de 5 veces, bloquear temporalmente la cuenta.
    • Registrar cada intento de inicio de sesión (éxito o fallo).
    • Validar que el usuario esté habilitado en el sistema antes de conceder acceso.
    • En caso de cuenta inactiva, ofrecer opción para contactar soporte o recuperar cuenta.
■ Decisions
    • Permitir el acceso solo a cuentas activas.
    • Implementar autenticación de dos factores (si aplica).
    • Permitir recordar sesión solo en dispositivos seguros.
    • Mostrar mensajes de error sin revelar cuál campo está mal (por seguridad).
■ Follow-up
    • Verificar si es necesario implementar CAPTCHA después de múltiples intentos fallidos.
    • Evaluar mecanismos de recuperación de cuenta (correo, SMS, preguntas de seguridad).
    • Revisar políticas de duración de sesión y cierre automático.

Scenario
Steps
1. El usuario ingresa su nombre de usuario.
2. El usuario ingresa su contraseña.
3. El usuario hace clic en el botón "Iniciar Sesión".
4. El sistema verifica si el nombre de usuario existe en la base de datos.
5. El sistema verifica si la contraseña ingresada es correcta.
6. El sistema verifica si la cuenta del usuario está activa.
7. Si todas las validaciones son correctas, el sistema concede acceso al usuario.
8. El sistema redirige al usuario a la página principal o al dashboard.

Scenario2
Steps
1. El sistema detecta que el usuario o contraseña son incorrectos.
2. El sistema muestra un mensaje: "Usuario o contraseña inválidos".
3. El usuario permanece en la pantalla de inicio de sesión.

Scenario3
Steps
1. El sistema detecta que la cuenta del usuario está inactiva.
2. El sistema muestra un mensaje: "La cuenta está inactiva. Contacte a soporte."

Preconditions El usuario ya tiene una cuenta registrada en el sistema. El sistema está en línea y accesible. La base de datos de usuarios está disponible.
Post-conditions El usuario ha iniciado sesión correctamente y tiene acceso a su área personalizada. El sistema ha denegado el acceso y ha notificado el motivo del fallo (credenciales inválidas o cuenta inactiva).
