Description

describe cómo los usuarios acceden y consultan el detalle de una solicitud de mantenimiento. El sistema valida permisos, recupera la información desde la base de datos y la presenta de manera clara, incluyendo datos del activo, descripción del problema, estado actual, técnico asignado y fechas relevantes.

Use Case Note
■ Workflow
    • El usuario accede al módulo de solicitudes, busca una solicitud y el sistema muestra su información detallada.
■ Business Logic
    • Los usuarios solo pueden consultar las solicitudes creadas por ellos, salvo que tengan permisos mayores.
    • Los gestores y administradores pueden consultar todas las solicitudes.
    • Se debe mostrar el historial de cambios y actualizaciones.
■ Decisions
    • Definir si los técnicos solo ven solicitudes asignadas o todas las de su área.
    • Determinar si la consulta incluye documentos adjuntos o solo texto.
■ Follow-up
    • Posibilidad de exportar la información para reportes.

Scenario
Steps
1. Tecnico de Mantenimiento
2. Administrador
3. Responsable
4. El usuario accede al sistema e ingresa al módulo Consultar Solicitud.
5. El sistema solicita criterios de búsqueda (ID, activo, estado, fecha, responsable).
6. El usuario ingresa los criterios y confirma la búsqueda.
7. El sistema recupera de la base de datos las solicitudes que cumplen los criterios.
8. El sistema muestra la lista de solicitudes encontradas.
9. El usuario selecciona una solicitud específica.
10. El sistema muestra el detalle de la solicitud (activo, descripción, estado, prioridad, técnico asignado, historial de cambios).
11. El caso de uso finaliza mostrando la información solicitada.

Scenario2
Steps
1. 6(a). El usuario no ingresa criterios → el sistema muestra mensaje indicando que se requieren datos de búsqueda mínimos.
2. 7(a). No existen solicitudes que cumplan los criterios → el sistema informa que no se encontraron resultados.
3. 9(a). El usuario intenta acceder a una solicitud sin permisos → el sistema bloquea el acceso y muestra mensaje de restricción.
4. 10(a). Error en la base de datos → el sistema informa fallo y no muestra resultados.
